# Минимальный приёмник EchM на Python

Отдельный проект для получения показаний каналов через COM-порт. Старые исходники,
профили и EXE не изменяются. Реализован **только Single**: один набор содержит по
одному значению для каждого включённого канала. PCA/PLS, графиков, истории,
электрической калибровки и экспорта Lumex здесь нет.

**Совместимость с реальным прибором ещё не проверена.** Перед подключением закройте
старую программу и остальные приложения, использующие этот порт. Новый клиент
отправляет команды остановки, настройки и запуска: это изменяет состояние прибора.

## Окружение

Python **3.10+**, фактически тестируется в этой рабочей копии на Python 3.14.
Внешняя зависимость одна: `pyserial==3.5`; тесты используют стандартный `unittest`.
Локальная `.venv` уже создана, зависимость установлена. На другом компьютере из
директории `python_reader` выполните в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Команды ниже не требуют активации окружения и изменения ExecutionPolicy.
При желании активация: `.\.venv\Scripts\Activate.ps1`.
В Linux/macOS используйте `.venv/bin/python` вместо Windows-пути; аппаратная
совместимость на этих платформах не проверена. Старые бинарные настройки читаются
по явно заданному little-endian MSVC layout, независимо от платформы Python.

## Начать без прибора

```powershell
.\.venv\Scripts\python.exe -m com_reader --check-config
.\.venv\Scripts\python.exe -m com_reader --demo
```

Деморежим **не открывает COM-порт** и генерирует явно синтетические значения раз
в 0.25 секунды. Он проверяет интерфейс, команды, потоковый парсер и ожидание по Enter,
но не доказывает совместимость с аппаратурой. Его период не равен интервалу профиля.

После запуска:

- **Enter** — ждать следующий полный принятый набор и вывести одну CSV-строку;
- **h + Enter** или **? + Enter** — справка;
- **q + Enter**, **Ctrl+C** или EOF — остановка и закрытие порта.

Подсказки, состояние и ошибки выводятся в **stderr**. В **stdout** попадают только
строки измерений. `--header` добавляет один CSV-заголовок с физическими номерами
каналов. Первая колонка — время получения на компьютере в UTC, не время прибора.

```text
2026-01-01T12:00:00.123+00:00,101,201,301,...
```

## Подключение к прибору

Сначала проверьте JSON и правильный порт:

```powershell
.\.venv\Scripts\python.exe -m com_reader --list-ports
.\.venv\Scripts\python.exe -m com_reader --check-config
.\.venv\Scripts\python.exe -m com_reader --port COM4 --trace wire.jsonl --header
```

`--port` переопределяет порт только для этого запуска. Настройки по умолчанию берутся
из `config.json` рядом с проектом, независимо от текущей директории. Другой файл:
`--config other.json`. Путь `--trace` задаётся относительно текущей директории;
существующий файл дополняется. Каждая запись JSONL содержит UTC-время, `tx`/`rx`,
точные байты в hex и длину. Эти данные остаются локальными; файл может содержать
измерения, поэтому не публикуйте его автоматически.

### Что означает Enter

Прибор постоянно передаёт данные после START. Фоновый поток принимает и разбирает
их, не сохраняя историю. Enter запрашивает **первый следующий полный набор**, а не
возвращает последний закэшированный результат. Набор, часть которого уже была
прочитана до запроса, исключается. Один запрос не создаёт очередь измерений.

Это **программный запрос, не аппаратный триггер**: байты могли ожидать чтения в
приборе, USB-адаптере или драйвере ОС. Нельзя утверждать, что физическое измерение
началось после Enter. Отметка времени — время выдачи принятого набора. Для строгой
синхронизации потребуется документация прибора или отдельная проверка запуска.

Если новый полный набор не пришёл за `sample_timeout_seconds`, строка не выводится,
а консоль остаётся доступной. Ошибка фонового приёма немедленно сообщается в stderr;
если консоль в этот момент ждёт ввода, завершите её через Enter/q/Ctrl+C. Даже при
выходе через q после фоновой ошибки код завершения будет ненулевым.
Завершение пытается получить подтверждение STOP; если это не получилось, клиент
явно сообщает, что остановка прибора не подтверждена, но всё равно закрывает порт.
Отказ файла трассировки также считается ошибкой, но не блокирует аварийный STOP.
`command_timeout_seconds` — общий дедлайн записи команды и ожидания её ответа;
одиночное чтение ограничено `read_timeout_seconds`.

## Перенесённые настройки

`config.json` получен из **`../Release/EchM.prm`**. Исходный размер — 12416 байт.
JSON сохраняет имя профиля, имена каналов, SHA256 источника, опорные каналы,
длительность и 32 старых поправки нуля в разделе `legacy`.

Перенесены:

- порт **COM4**, скорость **128000 бод**, **8N1**;
- включённые физические каналы **1–10**;
- 32 параметра задержки каналов, все равны **1**;
- интервал **10 секунд**;
- фильтр **500 Гц** — это фильтр прибора, не частота выдачи наборов.

**Исходный режим был Cross; новый явно переключён на Single по требованию.**
Остальные параметры сохранены, но физическая эквивалентность измерений не заявляется.
Исходная длительность 5 минут остаётся метаданными; консоль работает до выхода.

В `measurement.channels` — уникальные **физические номера 1…32 в возрастающем порядке**.
В `measurement.channel_delays` — ровно 32 параметра, включая выключенные каналы.
Для включённого канала допустимы 1…256; при отправке значение уменьшается на один,
как в `MIPSSetAdcChar`. Это параметры старого протокола: единицы задержек в
интерфейсе и формулы старого кода не полностью согласованы, поэтому новый клиент
не пытается переосмыслить их физический смысл.

Оценка времени Single переносится буквально: целая часть суммы параметров
включённых каналов, делённой на 25; пауза — `max(1, (interval - estimate) * 10)`.
Целочисленное усечение соответствует `mintime` в `MainFrm.cpp`, не является новой
физической моделью. Значения, которые не помещаются в поля команды, отклоняются.

Сохранённые `legacy.zero_offsets` **не вычитаются**. В активном драйвере старого
проекта вычитание закомментировано. Числа декодируются как signed int16 без масштаба;
физические единицы не установлены. `zero_offsets_applied: true` отклоняется, чтобы
не создавать ложное впечатление поддерживаемой калибровки.

### Повторный импорт

```powershell
.\.venv\Scripts\python.exe -m com_reader.legacy ..\Release\EchM.prm --output imported.json
.\.venv\Scripts\python.exe -m com_reader.legacy ..\base.epf --port COM4 --filter-hz 500 --output profile.json
.\.venv\Scripts\python.exe -m com_reader --config imported.json --check-config
```

`.epf` — **бинарный профиль, не CSV**. Поддерживаются известные размеры 8584 и 8620
байт; `.prm` — ровно 12416 байт. Порт и фильтр отсутствуют в `.epf`, поэтому обязательны
в аргументах импорта. Неизвестные layouts, недопустимые bool/режимы/параметры
отклоняются. Кодировка строк по умолчанию `cp1251`, можно задать `--encoding`.
Импорт всегда выбирает Single и сохраняет первоначальный режим в `legacy`.
Существующий JSON не перезаписывается без `--force`; исходный файл перезаписать нельзя.

## Неуточнённые детали протокола

1. **Окончания данных.** В DOCX представлено `10`. Не доказано, что это два ASCII-байта
   на проводе. Конфигурация разрешает кандидаты `3130` (ASCII `10`), `0d0a` (CRLF),
   `0a` (LF). Это проверяемые гипотезы, не утверждение поддержки прибором всех вариантов.
   После захвата обмена оставьте фактическое окончание в `data_terminators_hex`.
   Парсер не выдаёт значения до получения целого разрешённого окончания и сообщает
   наблюдаемое окончание в stderr.
2. **Подтверждения.** Для STOP/configure/START проверяются маркеры `:C`/`:A`/`:B`,
   согласующиеся с исходниками. Полная форма ACK в старом коде не установлена.
   Код ACK фильтра неизвестен: принимается ответ с недатовым заголовком `:…`,
   его байты выводятся в диагностику; применение фильтра этим не доказано.
3. **RTS/DTR и flow control.** Старый код наследует часть DCB. В JSON `rts`, `dtr`
   равны `null`: используются defaults pyserial (обычно линии активны); `rtscts`,
   `dsrdtr`, `xonxoff` явно выключены. Это предположение, требующее проверки. Можно
   установить `rts`/`dtr` в `true` или `false` перед открытием, но некоторые драйверы
   всё равно кратковременно меняют линии при открытии порта.
4. **Single.** Документ содержит только Cross. Его 102 пакета подтверждают общую
   структуру и знаковое декодирование, но не аппаратную работу Single.
5. **Скорость.** 128000 взято из старого кода; поддержка зависит от драйвера адаптера.

При запуске выполняется STOP (до трёх попыток), затем фильтр, настройки Single и START.
STOP поставлен перед фильтром, чтобы не менять параметры во время старого потока.
Сброс входного буфера выполняется только на границах управляющих команд, не по Enter.
Сериалом владеет один поток, включая команды, приём и закрытие.

## Проверка без оборудования

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты покрывают бинарный импорт, проверку JSON, 99-байтовую команду настройки,
знаковые значения, все 102 пакета из `данные.docx`, фрагментацию и синхронизацию,
запросы после Enter, исключение частично принятого набора, ошибки/таймауты,
закрытие порта и разделение CSV stdout / подсказок stderr.
Fixtures автономны; Word, исходный DOCX и прибор для них не нужны. Отдельные
интеграционные тесты импорта проверяют исходные файлы, если они доступны.

## Структура

- `config.json` — перенесённые настройки, редактируемые человеком;
- `com_reader/config.py` — проверка настроек;
- `com_reader/legacy.py` — независимый импорт бинарных профилей;
- `com_reader/protocol.py` — команды и потоковый парсер без I/O;
- `com_reader/device.py` — единственный владелец порта, API `wait_next_sample()`;
- `com_reader/cli.py` — Enter/h/q, CSV;
- `com_reader/simulation.py` — явно синтетический транспорт;
- `tests/` — unittest и документные fixtures;
- `requirements.txt`, `.gitignore`, `pyrightconfig.json` — окружение и настройки редактора.

Другой источник события позже сможет вызывать тот же `Device.wait_next_sample()`
вместо консоли. Математическая постобработка остаётся отдельным этапом.
